There is nothing to operate: tChirp has no keybind, and park-kill detection runs on its own. The one in-game surface is `/tchirp`, which answers questions rather than changing anything. The rest of this page is what tChirp decides and when.

## What counts as a park kill

Three things have to be true at the moment a player leaves a vehicle:

1. They were in a **front seat** — driver or front passenger.
2. The vehicle's **siren was on** as of the last check before they left.
3. The vehicle's **model is in `Config.chirpAssignments`**.

Then the vehicle goes on the chirp list, and every client near it starts chirping it at a randomised interval.

## The siren is read before the exit, not after it

Killing the siren is *part* of a park kill. By the time the player is out of the seat, every provider correctly reports the siren as off — so a check taken at that moment returns `false` every single time and nothing would ever chirp.

So tChirp samples the siren every 500 ms while you are seated, and decides the exit against the **previous** sample.

<Callout type="warning" title="A hand-killed siren can still chirp">
A siren switched off by hand and then left within the same 500 ms window counts as a park kill. There is no way to tell the two apart after the fact: both look like "the siren was on a moment ago and the player is now outside".

So when you are testing, **let the ELS park-kill the siren** rather than switching it off yourself — otherwise you are measuring the window, not the feature.
</Callout>

## The front-seat rule

The same rule arms a chirp and clears it: a **front seat**, driver or passenger.

- Leaving a front seat with the siren on **arms** the chirp.
- Taking a front seat in a chirping vehicle **clears** it, immediately, for everyone.
- Nothing chirps while a front seat is occupied, even for the moment before the list catches up.

This is tLib's shared occupancy rule, the same one tELS, tRadar and tRadio use, so "who is operating this vehicle" means the same thing across the whole set.

## The chirp itself

The chirp is played with `PlaySoundFromEntity` on the vehicle, which is a **client-side, positional** sound. Every client near the car plays it in their own world, so it gets quieter as you walk away and a server that emitted it once would emit it for nobody.

Each chirp draws a fresh interval and a fresh duration from the configured ranges, so a row of parked cars does not fall into step. Every car's chirp is timed independently of the others.

## `/tchirp`

Open to anyone, no ACE. It reads the install back to you; there is nothing in it to set, because every tChirp setting is server-side `config.lua`.

| Row | Answers |
| --- | --- |
| Will chirp on park | Whether the car you are in has an entry in `Config.chirpAssignments`, and which sound. When it has none it prints the model hash, and says the key is the **spawn** name — not the display name on the row above it, and not what `/lvcdebug` reports |
| Siren right now | On or off, **and which provider answered**. On `auto` the first provider to claim a vehicle owns it and the ones below are never asked, so this is the row that explains a car that does not chirp |
| Chirping now | How many vehicles are on the list server-wide, as this client last heard it |
| Silence … *N*m away | The one action. Appears only when something is chirping within 50 m |
| Provider · *N* models configured | The provider and timing from `config.lua`, without the server console |

Every other row is a read-only readout. `Refresh` rebuilds them in place.

**Silence** takes the nearest chirping car off the list, the same as someone getting into it. It chirps again the next time it is parked with the siren on. Anyone can press it — the server accepts a removal from any player.

There is no `/tchirpedit`.

## Which provider answers

Each provider answers one of three things about a vehicle: **on**, **off**, or **not mine**. Only "not mine" falls through to the next one, which is what lets a single server run tELS cars and LVC cars at once — and what lets ALS, whose siren state the game engine never sees, stop the cascade before it reaches a check that would read every ALS car as siren-on forever.

Which provider owns a given car is the fact that explains most of what tChirp does or does not do, so it has its own page: [Siren systems](/docs/tChirp/siren-systems).

## What the server refuses

The park kill is noticed on the client that left the car, and the client tells the server. That means the message arrives from somewhere a player controls, so the server checks it against its own copy of `config.lua`:

| The server can | It requires |
| --- | --- |
| see the vehicle and its model | the tone to be **exactly** the one that model is assigned. A different configured tone is refused, not corrected |
| see the vehicle, and its model has no assignment | refused. An unconfigured model can never chirp |
| not see the vehicle at all | the tone to be one of the tones this server has configured somewhere |

That last row is an ordinary state, not a fault: a vehicle whose owner is mid-migration is briefly not in the server's view of the world, and a legitimate park kill can land in that window.

Both events are rate-limited per player, at 12 per 10 seconds.

<Callout type="warning" title="Clearing a chirp is not ownership-checked">
A removal is accepted from any player. The officer who parks a car and the officer who takes it out are routinely different people, so there is no owner to check against. The worst a forged removal can do is stop a chirp early.
</Callout>

## Cleanup

Two things take a vehicle off the list besides somebody getting in:

- The server sweeps entries whose vehicle no longer exists, every 5 seconds, with a 5-second grace period so a freshly parked car is not swept before the server's view of the world catches up.
- Stopping the resource stops and releases every sound it is playing.

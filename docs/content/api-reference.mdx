Two client exports, two client-side events, two commands. None of it is needed to use tChirp.

## Exports

Both client-side, and both `exports.tChirp`.

| Export | Parameters | Returns | What it does |
| --- | --- | --- | --- |
| `IsChirping` | `vehicle: number` | `boolean` | On the chirp list? Answers from the last list received, not the frame |
| `IsSirenActive` | `vehicle: number` | `boolean` | Siren on, per the owning provider. Respects `Config.sirenSystem` |

`IsSirenActive` reports the **siren**, not the lights and not park-kill state, so a park-killed car returns `false`.

<Callout type="danger" title="Call IsSirenActive on the local player's vehicle, and nothing else">
LVC, LVC Fleet, ELS-FiveM and ALS only answer for the vehicle you are in, and asking about another car **suppresses your own park kill**. See [Siren systems](/docs/tChirp/siren-systems#asking-about-a-vehicle-you-are-not-in).
</Callout>

## Events

Local, raised with `TriggerEvent`. Both fire on **every** client, not only the one that parked the car.

| Event | Arguments | When |
| --- | --- | --- |
| `tchirp:armed` | `netId: number` | A vehicle is now on the chirp list |
| `tchirp:cleared` | `netId: number` | A vehicle has left it |

## Network events

Everything the server accepts is [validated against `config.lua`](/docs/tChirp/usage#what-the-server-refuses). Only `AddChirpVehicle` is gated by [`Config.access`](/docs/tChirp/configuration#access).

| Event | Direction | Arguments |
| --- | --- | --- |
| `tchirp:AddChirpVehicle` | client → server | `netId`, `soundCfg: { sound, ref }` |
| `tchirp:RemoveChirpVehicle` | client → server | `netId` |
| `tchirp:RequestChirpList` | client → server | none |
| `tchirp:SyncChirpList` | server → client | `list` keyed by `netId` |

### The `tChirp:` spellings are gone in 2.0.0

Lowercase `tchirp:` is the only form; the verbs are unchanged. Rename every `tChirp:` name in your code: a stale listener never runs, a stale trigger goes nowhere.

<Callout type="warning" title="A wrong event name is silent in FiveM">
  Triggering an event nobody registered does nothing, with no console warning. If an integration
  stopped at 2.0.0, start here. If you subscribed to both spellings in 1.x, drop the `tChirp:` one.
</Callout>

## Commands

| Command | Who | What |
| --- | --- | --- |
| `/tchirp` | anyone, client-side | Status dialog, plus a Silence button. [Full row list](/docs/tChirp/usage#tchirp) |
| `tchirp_diag` | console, or `command.tchirp_diag` | Version, tLib version, access, provider, timing, counts, fresh config check |

`tchirp_diag` is `restricted`: `add_ace group.admin command.tchirp_diag allow`. It reports the configuration **at startup**, not the live table.

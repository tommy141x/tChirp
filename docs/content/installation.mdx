One dependency, no database, no NUI, no build step. Nothing is escrow-packed.

## Requirements

| Requirement | Detail |
| --- | --- |
| [tLib](/docs/tLib) | **v1.0 or newer**, free. tChirp refuses to start below it |
| A FiveM server | `lua54`, declared by tChirp itself |
| A siren system | tLS, JLS, LVC, LVC Fleet, ELS-FiveM or ALS — or none, and tChirp reads the plain GTA siren |

No siren system needs configuring: tChirp detects all six, and `Config.sirenResources` is only for a folder you renamed yourself. See [Siren provider](/docs/tChirp/configuration#siren-provider).

## Install

<Steps>

### Put the folder in place

Extract into `resources/`. The folder must be named exactly `tChirp`, no version suffix.

### Set the load order

```cfg
ensure tLib
ensure tChirp
```

Wrong order gives `No such export`.

### Check your vehicle list

Nothing chirps unless its model is in [`Config.chirpAssignments`](/docs/tChirp/configuration#vehicle-assignments), which ships with eight base-game police models and is also the on/off switch.

### Optionally, choose who may chirp

`Config.access` ships `mode = "everyone"`, so skipping this changes nothing. Hearing and silencing stay open to everyone whatever you set — see [Access](/docs/tChirp/configuration#access).

### Start it and read the console

```txt
  Version:  v2.0.0 — up to date
  Models:   8 vehicle model(s) configured
  Sirens:   auto
```

Config problems print **above** the banner, naming the key, what was expected, what was found and the fix. An error stops tChirp starting, leaving no `Models` row.

</Steps>

## Confirm it works

1. Get into a configured vehicle as the driver.
2. Turn the siren on.
3. **Let the ELS park-kill it** — put the car in park and let the siren cut out on its own.
4. Get out and walk a few metres away.

The car chirps within 4–6 seconds and keeps chirping until somebody sits in a front seat.

If nothing happens, run [`/tchirp`](/docs/tChirp/usage#tchirp) in the car: whether the model is configured and which provider answers explains nearly every silent install. Then set `Config.debug` and read [Troubleshooting](/docs/tChirp/troubleshooting).

## Verifying a change without a server

`bun install && bun run test:lua` checks your `config.lua` against tChirp's own test suites.

## Optional: help us fix tChirp

tChirp does not report its own faults to us. When it throws on your server the
error sits in your console, and unless someone opens a ticket we never learn it
happened — which means the bugs nobody reports are the ones that stay.

One line opts in, in `server.cfg` above `ensure tLib`:

```txt title="server.cfg"
set tlib_telemetry 1
```

That sends errors, warnings, renderer crashes and slow-operation outliers from
our own code. **No IP, no licence key, no server name, no player names or
identifiers**, and `<resource>_diag` output is never included. `tlib_telemetry_status`
in the console shows what is on and what decided it.

It is off unless you set it, nothing is gated behind it, and
[Diagnostics](/docs/tLib/telemetry) is the full account of what is and is not sent.

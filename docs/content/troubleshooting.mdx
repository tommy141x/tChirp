Set `Config.debug = true`, `restart tChirp`, and read which line is **missing**. `tchirp_diag` shows the configuration as read; `/tchirp` names the model and the answering provider.

## Nothing chirps at all

<Steps>

### Does it start?

No `Models` row in the banner means `config.lua` errored and the server half never started. The errors print above it.

### Is the model configured?

`Models` is the size of `Config.chirpAssignments`: `0` means nothing can chirp, `8` means the shipped models. Check your car's **spawn name** is one of them.

### Is the park kill detected?

```txt
[tChirp][DEBUG] park kill — vehicle 12345 (netId 67, sound VEHICLES_HORNS_POLICE_WARNING)
```

No line means the siren was never seen as on: your ELS is not one of the six and leaves no siren audio for the fallback to find ([My ELS is not one of these](/docs/tChirp/configuration#my-els-is-not-one-of-these)); or `Config.sirenSystem` is pinned to a provider that does not own this car; or you killed the siren by hand over 500 ms before getting out.

There was a third cause, fixed in the current 2.0 build: `Config.sirenSystem = 'lvc'` or `'lvc_fleet'` could **never** produce a park kill. LVC's own park kill zeroes its siren tone the instant you start getting out, about a second before you are clear of the seat, so tChirp always re-read the siren as off before it saw the seat empty. It no longer believes a siren-off that arrives while you are climbing out. No shorter poll interval would have helped — the zero always lands first.

### Did the server accept it?

```txt
[tChirp][WARN] player 3 asked for sound "VEHICLES_HORNS_SIREN_1" on netId 67, whose model is assigned "VEHICLES_HORNS_POLICE_WARNING" — refused
```

Client and server disagree about `config.lua`, almost always because only one was restarted — `restart tChirp` does both. Two sibling refusals name a model with no entry, or a sound in none.

### Did the list arrive?

`chirp list synced — 0 vehicle(s)` after a park kill means the add did not land. Look for the refusal above it.

### Are the front seats empty?

Nothing chirps while a front seat is occupied.

</Steps>

## Only some vehicles chirp

A model with no [entry](/docs/tChirp/configuration#vehicle-assignments) never chirps. Otherwise it is a malformed entry, reported at startup by model name — if you copied from the old GitBook page, check for `['police'] = 4`, a bare siren ID no released tChirp reads.

## Every park chirps, even with the siren off

**This was tChirp's own bug, and no config change worked around it.** A vehicle no provider claimed fell through to `IsVehicleSirenOn`, which reports the siren switch — and in GTA that switch is the light bar, so a unit parked at a scene with its lights on read as siren-on and every exit looked like a park kill. The current 2.0 build reads `IsVehicleSirenAudioOn` instead, so re-download it and unpin `Config.sirenSystem` if you pinned it to work around this.

Still happening on the current build means your ELS leaves GTA's own siren audio running after its own siren stops. See [My ELS is not one of these](/docs/tChirp/configuration#my-els-is-not-one-of-these).

## The chirp never stops

A **front** seat clears it; a rear seat does not. If it survives that, the vehicle is gone but its network ID is still listed, and those are swept every 5 seconds.

## Errors and config messages

| Message | Cause and fix |
| --- | --- |
| `requires tLib v1.0 or newer` | Update tLib |
| `No such export`, or tChirp fails to start | tLib was not started first. `ensure tLib` above `ensure tChirp` |
| `attempt to index a function value` | Same cause, or a tLib too old to have the module tChirp asked for |
| `Config.sirenSystem must be one of ...` | A provider name that does not exist. See [Siren provider](/docs/tChirp/configuration#siren-provider) |
| `chirpMinIntervalMs (...) is greater than chirpMaxIntervalMs (...)` | An inverted range. Unchecked, the chirp thread dies silently |
| `... is not a setting this resource reads` | A warning, not an error. The key is ignored and the default applies |

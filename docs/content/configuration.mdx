Everything is in `config.lua`. Edit the file, restart the resource. tChirp runs with zero edits.

## Access

Who may park-kill a car onto the chirp list. **The default is `everyone`.**

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `Config.access.mode` | string \| list | `"everyone"` | `everyone`, `ace`, `job`, `item`, `custom`, or a list of them |
| `Config.access.ace` | string | `"tchirp.use"` | For `mode = "ace"` |
| `Config.access.job` | table | `{ police = 0, sheriff = 0, statepolice = 0 }` | **name = minimum grade**; `0` accepts any |
| `Config.access.item` | string | `"police_radio"` | For `mode = "item"` |
| `Config.access.count` | number | `1` | How many of that item |
| `Config.access.custom` | function | `nil` | Takes a player id, returns `true` to allow |

A list passes if **either** entry does. Six frameworks and nine inventories resolve out of the box.

<Callout type="info" title="This gates adding a chirp, not hearing one or stopping one">
  A civilian beside a chirping patrol car hears it, and silencing is accepted from anyone.
</Callout>

## Siren provider

tChirp asks one question: **was the siren on?** The default, `auto`, covers every case below, including two ELS resources on one server.

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `Config.sirenSystem` | `auto` \| `tels` \| `lvc` \| `lvc_fleet` \| `els_fivem` \| `jls` \| `als` \| `native` | `"auto"` | Which system is asked whether the siren was on |
| `Config.sirenResources` | table | `{}` | Override, per provider, for a folder you renamed yourself |

| System | Read from | Name needed? | Notes |
| --- | --- | --- | --- |
| tLS | `exports[name]:IsSirenActive(vehicle)` | No | `tLS` and `tELS` are both recognised |
| JLS | `exports[name]:IsSirenActive(vehicle)` | No | `Burkhardt_Software_JLS` and `Jace3483_JLS` are both recognised |
| Luxart Vehicle Control | `lvc:UpdateThirdParty` event | No | On when the tone is above zero |
| LVC Fleet | the same event as LVC | No | |
| ELS-FiveM | `els:setSirenState_c` event | No | |
| Advanced Lighting System | the four `ALS:*SirenClient` events | No | **Either** siren counts as on |
| Plain GTA siren | `IsVehicleSirenAudioOn(vehicle)` | No | The fallback when nothing else claims the car |

Only tLS and JLS are asked by export, so they are the only two whose folder name matters at all — and tChirp knows the names both of them ship under, current and previous, and uses whichever is actually running. Fill in `Config.sirenResources` only if you renamed a folder to something of your own. A name there that is not a started resource is ignored rather than trusted, so an old config pinning a name that has since changed upstream still works.

<Callout type="info" title="The GTA fallback reads siren audio, not the light bar">
`IsVehicleSirenOn` sounds like the right native and is not: it reports the siren **switch**, and in GTA that switch is the light bar. A unit parked at a scene with its lights on reads as siren-on, so every exit looked like a park kill. The fallback reads `IsVehicleSirenAudioOn` instead, which is false when the lights are up and the audio is silent. Changed in 2.0.1; if you pinned `Config.sirenSystem` to work around the old behaviour, unpin it.
</Callout>

### The cascade order

With `auto`, the first provider that recognises the vehicle answers:

```txt
tels → lvc / lvc_fleet → els_fivem → jls → als → native
```

<Callout type="warning" title="Pinning removes the fallback as well as the other providers">
`Config.sirenSystem = 'tels'` consults that provider only. A vehicle it does not recognise is treated as siren-off and never chirps. Pin only when you run exactly one ELS and would rather a wrong answer be loud.
</Callout>

### Your ELS kills the siren when you get out

Most do, LVC included — it is the same "park kill" idea, applied to the siren rather than to a reminder. It makes the park kill hard to see, because the evidence deletes itself: LVC zeroes its tone the instant you start climbing out and tells tChirp so about a second before you are actually out of the seat.

tChirp handles that by not believing a siren-off that arrives while you are getting out. It applies to LVC, LVC Fleet, ELS-FiveM and ALS, and it means **you do not have to turn your ELS's own park kill off** to use tChirp. A siren you switch off yourself while sitting in the car is still a siren off, and that car will not chirp.

<Callout type="info" title="On LVC, leave Config.sirenSystem on auto">
Pinning to `lvc` is not needed and costs you the fallback. `auto` reaches the LVC rung for any car LVC has reported a tone for, and the GTA fallback below it is silent on an LVC car anyway: LVC mutes GTA's own siren audio on the cars it controls, so the fallback cannot false-positive there. Before 2.0.1, `lvc` could never chirp at all — if that is why you pinned it, unpin it.
</Callout>

### Asking about a vehicle you are not in

LVC, ALS and ELS-FiveM only answer for **the vehicle you are in**. Asking `IsSirenActive` about any other car both gets a useless answer and **suppresses your own park kill**, so do not poll nearby traffic.

### My ELS is not one of these

Nothing claims your vehicles, so every park falls through to the native check, which reads GTA's siren **audio**.

| Symptom | What happened |
| --- | --- |
| Nothing ever chirps | Your ELS plays its own siren sounds and mutes GTA's, so there is no audio for the fallback to find. This is the common case, and it is not fixable from config |
| Every park chirps, siren off | Your ELS leaves GTA's siren audio running after its own siren stops |

Pinning `Config.sirenSystem` to the closest match is a workaround, not a fix, and it is the wrong first move: a provider that does not recognise your cars answers "siren off" for all of them, so pinning can turn a resource that chirps too often into one that never chirps. Report your ELS instead and it can be supported directly, as ALS is — what is needed from it is an export or an event that says whether the siren is sounding.

## Chirp timing

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `Config.chirpMinIntervalMs` | number ≥ 1 | `4000` | Shortest gap between chirps, ms |
| `Config.chirpMaxIntervalMs` | number ≥ 1 | `6000` | Longest gap between chirps, ms |
| `Config.chirpMinDurationMs` | number ≥ 1 | `75` | Shortest chirp, ms |
| `Config.chirpMaxDurationMs` | number ≥ 1 | `125` | Longest chirp, ms |
| `Config.debug` | boolean | `false` | `DEBUG` log level on client and server |

Ranges are inclusive and drawn fresh per chirp. Min equal to max gives a fixed value; min above max is refused at startup; there is no upper bound. `Config.debug` prints a line per park kill, sync, chirp and refusal — leave it off on a live server.

## Vehicle assignments

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `Config.chirpAssignments` | table | eight base-game police models | Spawn name → the sound that model chirps |

```lua
Config.chirpAssignments = {
    ['police']  = { sound = 'VEHICLES_HORNS_POLICE_WARNING', ref = 0 },
    ['police2'] = { sound = 'SIREN_PRIORITY', ref = 'DLC_WMSIRENS_SOUNDSET' },
}
```

`sound` goes to `PlaySoundFromEntity`; `ref` is a soundset name or `0` for these:

| `sound`, with `ref = 0` | What it is |
| --- | --- |
| `VEHICLES_HORNS_POLICE_WARNING` | Short attention chirp. The default |
| `VEHICLES_HORNS_SIREN_1` | Wail |
| `VEHICLES_HORNS_SIREN_2` | Yelp |
| `VEHICLES_HORNS_AMBULANCE_WARNING` | Powercall |

A malformed entry — no `sound`, or a bare number where the table belongs — is reported at startup **by model name**, not skipped.

<Callout type="info" title="This table is also the on/off switch">
A model with no entry never chirps. `{}` is a supported "nothing chirps" state, and deleting the key entirely is equivalent.
</Callout>

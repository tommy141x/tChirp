Everything is in `config.lua`. There is no database, no in-game panel and no escrow: edit the file, restart the resource.

tChirp runs with zero edits. Nothing here is required, and a key you delete comes back as the value the shipped file carries.

## The two you will actually change

| Option | Why |
| --- | --- |
| `Config.chirpAssignments` | Ships with the eight base-game police models. Your server runs different ones |
| `Config.sirenSystem` | `auto` covers a mixed fleet. Pin it if you run exactly one ELS and want a wrong answer to be loud |

## Full reference

### Siren provider

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `Config.sirenSystem` | string: `auto` \| `tels` \| `lvc` \| `lvc_fleet` \| `els_fivem` \| `jls` \| `als` \| `native` | `"auto"` | Which siren system is asked whether the siren was on. `auto` cascades through all of them |
| `Config.sirenResources` | table | `{ tels = 'tELS', jls = 'Jace3483_JLS' }` | Folder names of the two **export-based** providers. Only change these if you renamed tELS or JLS |

`auto` tries providers in this order and takes the first one that recognises the vehicle:

```txt
tels → lvc / lvc_fleet → els_fivem → jls → als → native
```

A provider that does not recognise the vehicle passes, which is what makes a mixed fleet work: tELS cars are answered by tELS and LVC cars by LVC on the same server. `native` is last because it always answers, so it can only ever be the fallback.

<Callout type="warning" title="Pinning a provider is not a small change">
`Config.sirenSystem = 'lvc'` means LVC and nothing else. A vehicle LVC does not know about is then reported as "siren off" and never chirps — there is no fall-through to the native check. Use `auto` unless you have a reason.
</Callout>

### Chirp timing

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `Config.chirpMinIntervalMs` | number ≥ 1 | `4000` | Shortest gap between chirps, in ms |
| `Config.chirpMaxIntervalMs` | number ≥ 1 | `6000` | Longest gap between chirps, in ms |
| `Config.chirpMinDurationMs` | number ≥ 1 | `75` | Shortest chirp, in ms |
| `Config.chirpMaxDurationMs` | number ≥ 1 | `125` | Longest chirp, in ms |

Both ranges are inclusive and are drawn fresh for every chirp, so no two chirps are identical. Setting a minimum equal to its maximum is legal and gives a fixed value.

Setting a minimum **above** its maximum is refused at startup, with the file, both keys and both values named. That check exists because the alternative is a bare `bad argument #2 to 'random' (interval is empty)` thrown inside a thread, which kills every chirp for the rest of the session and names nothing.

There is no upper bound on any of the four. The code does not enforce one, and a limit you cannot argue with is worse than none.

### Vehicle assignments

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `Config.chirpAssignments` | table | eight base-game police models | Vehicle spawn name → the sound that model chirps |

```lua
Config.chirpAssignments = {
    ['police']  = { sound = 'VEHICLES_HORNS_POLICE_WARNING', ref = 0 },
    ['ambulance'] = { sound = 'VEHICLES_HORNS_AMBULANCE_WARNING', ref = 0 },
}
```

| Field | Type | What it is |
| --- | --- | --- |
| `sound` | string | The native sound name passed to `PlaySoundFromEntity` |
| `ref` | string or `0` | A soundset name, or `0` for the standard native sounds |

Sounds that need no extra resource, with `ref = 0`:

| `sound` | What it is |
| --- | --- |
| `VEHICLES_HORNS_POLICE_WARNING` | Short attention chirp. The shipped default |
| `VEHICLES_HORNS_SIREN_1` | Wail — a long continuous tone |
| `VEHICLES_HORNS_SIREN_2` | Yelp |
| `VEHICLES_HORNS_AMBULANCE_WARNING` | Powercall / ambulance chirp |

If you already run WM Sirens, its soundset works as a `ref`:

```lua
['police'] = { sound = 'SIREN_PRIORITY', ref = 'DLC_WMSIRENS_SOUNDSET' },
```

<Callout type="info" title="This table is also the on/off switch">
A model with no entry never chirps. Deleting an entry is how you stop that model chirping, and an empty table is a supported state — tChirp loads and does nothing.
</Callout>

A malformed entry — a missing `sound`, or a bare number where the table belongs — is reported at startup by model name rather than skipped. A silently skipped entry is one car that never chirps while every other one does, which is the hardest version of this to notice.

### Diagnostics

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `Config.debug` | boolean | `false` | Lowers tChirp's log level to `DEBUG` on both the client and the server |

With it on you get a line for every park kill, every list sync, every chirp and every refusal. Leave it off on a live server: a busy department produces a line per chirp per parked car.

## Renamed in 1.1.0

Your 1.0.0 `config.lua` keeps working. Each old name carries its value onto the new one and prints one warning naming the replacement. The old names stop working in 2.0.0.

| 1.0.0 | 1.1.0 |
| --- | --- |
| `Config.ChirpMinInterval` | `Config.chirpMinIntervalMs` |
| `Config.ChirpMaxInterval` | `Config.chirpMaxIntervalMs` |
| `Config.ChirpMinDuration` | `Config.chirpMinDurationMs` |
| `Config.ChirpMaxDuration` | `Config.chirpMaxDurationMs` |
| `Config.ChirpAssignments` | `Config.chirpAssignments` |
| `Config.Debug` | `Config.debug` |

The durations gained an `Ms` suffix because `chirpMinInterval = 4` cannot be read as four seconds once the unit is in the name.

## Settings that are gone

| Setting | What happened |
| --- | --- |
| `Config.LVCResourceName` | **Not read by 1.0.0 either**, though the old GitBook page documents it. LVC is detected from the `lvc:UpdateThirdParty` event, which arrives under that name regardless of what the sending resource is called, so there is nothing for a resource name to be used for. 1.1.0 reports it as doing nothing instead of ignoring it |
| `Config.sirenResources.lvc` | Same reason. LVC needs no resource name, so carrying one that the code did not read — while telling owners to change it if their resource was renamed — was worse than having none |

<Callout type="warning" title="The old GitBook page describes a different assignment format">
It documents `Config.ChirpAssignments` as a map of vehicle name to a **siren ID from `lvc/SIRENS.lua`**, as in `['police'] = 4`. tChirp 1.0.0 — the version this documentation replaces — already did not read that: its value was a table of a native sound name and a soundset, exactly as above. A bare number is now reported as an error at startup rather than silently ignored.
</Callout>
